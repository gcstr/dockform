# Dockform (for AI agents)

Dockform {{.Version}}. Generated by `dockform llm`.

Dockform deploys Docker Compose stacks to one or more hosts from a manifest
(`dockform.yml`) and a directory layout. Nothing is installed on the hosts and
there is no state file: everything dockform creates carries the Docker label
`io.dockform.identifier=<identifier>`, and those labels are the state.

## How it works

- **Desired state is the manifest plus the directories.** `plan` compares it
  with what the Docker daemons run; `apply` makes them match, then removes
  labeled resources that are no longer declared.
- **Contexts are hosts.** Each key under `contexts:` is a Docker context name
  (`docker context ls`), or a name with `host: ssh://user@host`. Remote hosts
  are reached over SSH.
- **Stacks are discovered.** A directory `<context>/<stack>/` containing a
  compose file is the stack `<context>/<stack>`. Files in it are picked up by
  name:

  | Path | Meaning |
  |---|---|
  | `<context>/<stack>/compose.yaml` | the stack's compose file (also compose.yml, docker-compose.yaml, docker-compose.yml) |
  | `<context>/<stack>/environment.env` | env file for compose interpolation |
  | `<context>/<stack>/secrets.env` | SOPS-encrypted dotenv, decrypted at apply and passed as env |
  | `<context>/<stack>/volumes/<name>/` | fileset: synced into the volume `<stack>_<name>` |
  | `<context>/secrets.env` | SOPS secrets shared by every stack in the context |

- **Explicit stacks** (`root:` in the manifest) are for directories outside
  that layout. They are not discovered, so nothing above is loaded for them
  automatically.
- **Secrets never touch disk.** Decrypted values go to compose as environment
  variables, and the rendered compose document is piped over stdin. They reach
  a container only through its `environment:` list (see below).

## Manifest reference

Every key, in one annotated example. Only `identifier` and `contexts` are
required.

```yaml
identifier: homeserver            # label value on everything dockform creates

sops:                             # needed when any secrets file exists
  age:
    key_file: ${AGE_KEY_FILE}
    recipients: [age1...]
  # or pgp: {keyring_dir, use_agent, pinentry_mode, recipients, passphrase}

discovery:                        # optional; these are the defaults
  compose_files: [compose.yaml, compose.yml, docker-compose.yaml, docker-compose.yml]
  environment_file: environment.env
  secrets_file: secrets.env
  volumes_dir: volumes

contexts:
  hetzner-one:                    # a docker context name
    host: ssh://deploy@203.0.113.10   # optional: use this host instead
    volumes:
      shared-data: {}             # created and labeled by dockform
      backups: {destroy: false}   # left in place by `dockform destroy`
    networks:
      traefik:
        driver: bridge            # also: options, internal, attachable, ipv6,
                                  # subnet, gateway, ip_range, aux_addresses, destroy
  hetzner-two: {}                 # nothing to declare: just a host with stacks

deployments:                      # named groups for --deployment
  web:
    description: Public web services
    contexts: [hetzner-one]
    stacks: [hetzner-two/traefik]

stacks:                           # optional: add to discovered stacks, or declare explicit ones
  hetzner-one/navidrome:          # a discovered stack, with additions
    profiles: [production]
    environment:
      inline: [LOG_LEVEL=info]    # wins over environment.env
    project: {name: music}        # compose project name (default: compose's own)
    filesets:
      config:                     # override the discovered volumes/config fileset
        source: volumes/config    # local directory, relative to the stack
        target_volume: navidrome_config   # default: <stack>_<name>
        target_path: /
        apply_mode: hot           # hot (default): sync, then restart; cold: stop, sync, start
        restart_services: attached   # services mounting the volume; or a list
        exclude: ["*.tmp"]
        ownership: {user: "1000", group: "1000", file_mode: "0644", dir_mode: "0755", preserve_existing: false}
  hetzner-one/legacy:             # an explicit stack
    root: ../apps/legacy
    files: [docker-compose.yml, docker-compose.prod.yml]
    env-file: [app.env]
    secrets:
      sops: [secrets/app.env]     # explicit stacks only; deprecated on discovered ones
```

- `${VAR}` in the manifest is read from the environment. An unset variable
  becomes empty, with a warning.
- `environment.files` is not supported: use the stack's `environment.env` or
  `environment.inline`.
- A service opts into tag upgrades with the compose label
  `dockform.tag_pattern`, e.g. `"^\\d+\\.\\d+\\.\\d+$$"` (compose needs `$$`
  for a literal `$`).

## Writing compose files for dockform

Compose doesn't enforce these, so getting them wrong fails silently:

1. **Fileset volumes are external.** Declare `<stack>_<fileset>` with
   `external: true`. Otherwise compose creates its own empty
   `<project>_<name>` volume, and the synced files never show up.
2. **Context networks and volumes are external too.** Anything under
   `contexts.<ctx>.networks` or `contexts.<ctx>.volumes` is created by
   dockform: reference it by its exact name with `external: true`.
3. **Env and secrets reach a container only when listed.** Values from
   `environment.env`, `secrets.env` and `environment.inline` are variables for
   compose. A service gets one only through its `environment:` list, or a
   `${VAR}` elsewhere in the file.

A complete stack:

```
hetzner-one/web/
├── compose.yaml
├── environment.env        # SITE_NAME=Example
├── secrets.env            # SOPS-encrypted: DB_PASSWORD=...
└── volumes/
    └── config/            # fileset "config", synced into the volume web_config
        └── default.conf
```

```yaml
# hetzner-one/web/compose.yaml
services:
  web:
    image: nginx:1.27
    environment:
      - SITE_NAME            # from environment.env
      - DB_PASSWORD          # from secrets.env
    volumes:
      - web_config:/etc/nginx/conf.d:ro
    networks: [traefik]

volumes:
  web_config:
    external: true           # the fileset's volume

networks:
  traefik:
    external: true           # declared in dockform.yml, below
```

```yaml
# dockform.yml
identifier: homeserver
contexts:
  hetzner-one:
    networks:
      traefik: {}
```

## Commands

Global: `--manifest <path>`, `--ssh-transport tunnel|mux|direct` (default
tunnel), `--log-level debug|info|warn|error`, `-v`.
Targeting (plan, apply, destroy, images): `--context <ctx>`,
`--stack <ctx/stack>`, `--deployment <name>`.

| Command | What it does |
|---|---|
| `plan [--long]` | Show what apply would change. Read-only. |
| `apply [--skip-confirmation] [--parallel N]` | Plan, ask, apply, prune. Writes a debug log to `.dockform/logs/`. |
| `destroy [--skip-confirmation]` | Remove everything with this identifier. Asks you to type the identifier. |
| `validate` | Check the manifest, compose files and daemons. |
| `doctor` | Check local tools and reach every context. |
| `images check [--all] [--json]` | Per service: newer tags (needs tag_pattern), digest drift, not applied. |
| `images upgrade [--dry-run]` | Rewrite image tags in compose files. Then run apply. |
| `images pull [--recreate] [--dry-run]` | Pull same-tag images whose digest moved; `--recreate` restarts those services, after asking. |
| `volume snapshot <ctx/volume>` | Save a volume to `.dockform/snapshots/`. |
| `volume restore <ctx/volume> <snapshot> [--stop-containers] [--force]` | Restore a snapshot into an existing volume. |
| `secrets create <path>`, `secrets edit <path>`, `secrets decrypt <path>`, `secrets rekey` | Manage SOPS dotenv files. |
| `compose render [stack]` | Print a stack's resolved compose document, secrets masked. |
| `manifest render` | Print the manifest after `${VAR}` interpolation. |
| `init` | Create a starter dockform.yml. |
| `dashboard` | Full-screen TUI, for humans. |

`dockform <command> --help` lists every flag.

## Common tasks

- **Add a stack**: create `<context>/<name>/compose.yaml`, then `plan` and `apply`.
- **Add a secret**: `dockform secrets edit <context>/<stack>/secrets.env`,
  list `NAME` under the service's `environment:`, then apply.
- **Ship config files into a container**: put them in
  `<context>/<stack>/volumes/<name>/` and mount the volume `<stack>_<name>`,
  declared `external: true`.
- **Update images**: `images check`. New tags: `images upgrade`, then `apply`.
  Same tag, new content: `images pull --recreate`.
- **Work on one host or stack**: add `--context <ctx>` or `--stack <ctx/stack>`.
- **When something fails**: `dockform validate` checks the manifest and compose
  files, `dockform doctor` checks tools and hosts, and every apply leaves a
  debug log in `.dockform/logs/`.
- **Anything not covered here**: https://dockform.io/ (manifest and command
  reference), or `dockform <command> --help`.

## Rules for agents

- Show `dockform plan` before `apply`. Don't pass `--skip-confirmation` unless asked.
- Never run `destroy` unless asked: it deletes volumes, and their data, unless
  they are marked `destroy: false`.
- Never print secret values: no `secrets decrypt`, no `compose render --show-secrets`.
- On remote contexts, don't bind-mount local paths: the daemon would resolve
  them on the remote host, and dockform rejects them. Use a fileset.
- In `images` output, `not applied` means run `apply`; `digest changed` means
  `images pull --recreate`.
- `--parallel` limits docker calls per host (default 2), not containers.
